# Q6.2 语义复查收敛基线

本阶段建立离线回归集，不修改生产提示词、复查策略、默认质量或磁盘协议。Q6.2 的当前模型收敛实测仍未完成。

## 历史证据与限制

2026-10-11 在代码基线 `334c634` 下只读检查下载目录中的全部 20 个历史 Job，其中 9 个为 polished，7 个保留已接受的人工译文修订。读取 39 份语义报告和 26 次已接受修订，按父报告内容 checksum 与 changed_ids 得到 22 条唯一报告转换；另 4 次缺父报告或后续报告，不推测顺序。扫描前后 450 个 JSON/JSONL 文件的内容 checksum 一致。

以 `category + cue_ids` 为问题键，这些转换累计新增 35、保留 40、后续报告不再出现 26 个问题键。这是观察次数，不是唯一缺陷数；同一键可能对应不同遗漏，“不再出现”也不等于已证实解决。旧模板不算已接受修订，文件时间不用于证明报告关系。

对历史 results 的 173 个批次使用当前解析器离线重放：172 个通过，1 个旧 v2 批次因建议文本没有变化被拒绝。重放验证响应结构，不验证完整历史 Job 的 fingerprint 链，也不重新调用模型。

按完整记录批次字段（源文、候选、上下文、语言、策略、语义组和协议版本）比对，发现 7 组输入相同但原始批次 issues 不同的记录。其中 2 组的源文疑点仍被最终报告保留，不能算丢失。合并后有 5 组问题键差异：1 组来自旧 v2，另 4 组记录为 v4。它们可作为稳定性实验线索，但历史文件未保存完整模型请求参数与当时提示词正文，不能据此断言当前完整请求相同或当前模型存在复现缺陷。

未找到留存的“可接受/无需报告却登记为问题”实例，不代表历史上没有发生。关键词检索只用于发现候选，不是生产过滤规则。

## 最小回归样本

样本位于 [q62-semantic-samples.json](../tests/fixtures/q62-semantic-samples.json)，测试位于 [test_semantic_convergence.py](../tests/test_semantic_convergence.py)。只保存短字幕片段；ID 重新编号，时间戳在测试中合成，不声称保留原 Job 时间轴。完整历史报告、凭据、本地路径、媒体和原始远端元数据不入库。

每类样本记录来源报告的内容 checksum、原 cue ID 与历史 prompt version，便于本地追溯；环境变量的三版译文来自不同轮次，checksum 指向基准轮。英文源文仅展开换行，issue message 为精简说明，不声称逐字保存完整历史响应。version 字段只描述 fixture 格式，不是新增运行时协议。

| 样本 | 文本判断与覆盖 |
| --- | --- |
| 环境变量 | 三版候选分别遗漏选择关系、environment 限定和 use 动作；同 cue、同 omission 键仍可能是新的真实问题。接受完整修订响应，并保持确定性 glossary QA 对缺失必需术语的阻断。 |
| 相邻谓语 | 修改前句后，后句仍重复“是一个”。复查和修复覆盖完整语义组，拒绝不完整修复；保留邻组文本、ID、顺序、源文和时间轴。 |
| mod/model 源文疑点 | 无原音确认的源文真值，保持未决。合并函数保留已传入的疑点，源文疑点不产生自动源文或译文修复建议；无关自动修复后的完整流程保留行为另由既有 pipeline 测试覆盖。 |
| 旧无变化建议 | 历史建议为最后一个 cue 返回完全相同的文本；当前解析器拒绝，不能将旧缺陷登记为当前待修项。 |

样本的判断由当前 Agent 对字幕文本独立审阅，不是外部人工验收或原音事实确认。测试只验证确定性边界，不能证明模型会正确检出这些问题。日语名词化细节、专名和源文音频疑点保留为后续人工 oracle 工作，不强行转为断言。

另有合成响应测试：message 包含“其他表达可接受”，但仍明确描述真实遗漏；结构化 meaning_error/omission 不得按消息关键词被吞掉。该响应是边界对照，不冒充找回的历史矛盾报告。

## 指标与后续验收

每轮记录源文、候选和完整请求的内容 checksum、模型参数、实际 prompt/grouping 版本、复查范围及问题证据，分别统计：

- 独立 oracle 认可的真实问题检出与漏报，不把模型建议本身当真值。
- 无依据的问题、仅风格偏好的误报，以及源文疑点未决数。
- 新增、保留、解决的问题：按具体遗漏或错误关系判定，不只按 issue 键计数。
- 修订引入的新问题、重复往返与有效人工修改轮数；不能仅以 needs_review 下降宣称优化。

后续真实 API 实验需要单独授权，固定完整输入并重复运行短样本。源文 oracle 未确认的样本单独报告；初审漏报、复审新发现与自相矛盾分别分类。没有收益证据前不修改生产策略，不采用关键词黑名单或多数投票自动放行，不放宽确定性 QA。

默认仍为 `standard + faithful`。离线基线完成后继续模型收敛实测，Q6.2 验收通过再进入 R3.1 / R3.2；见 [路线图](../ROADMAP.md)。
